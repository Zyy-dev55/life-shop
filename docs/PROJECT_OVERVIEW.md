## 二、项目定位与背景

本系统是一套**可完整运行的多店铺 B2C 生活用品电商系统**，不是静态演示页面。
它把「浏览 → 咨询 → 加购 → 结算 → 支付 → 商家发货 → 物流追踪 → 确认收货 →
评价 → 售后退款 → 商家提现 → 平台监管」整条业务闭环落到一个单端口服务里，
并在这个业务系统之上叠加了**网络安全加固与智能运维监测**能力，
使其同时具备网络工程专业的组网、协议、安全与运维实践要素。

技术栈：`Java 8/17 · SpringBoot 2.7 · MyBatis-Plus · MySQL 8 / H2 · JWT ·
Vue 3 · Vite · Pinia · Element Plus`。
内置演示数据：6 家店铺 / 6 大类 / 48 件商品 / 65 条评价 / 70 笔订单 / 8 组客服会话。

## 四、系统架构与网络分层

```
浏览器 / Vue3 SPA  ──HTTP/1.1 + JSON + JWT──┐
                                            │（可选 Nginx 反向代理，透传 X-Forwarded-For）
┌───────────────────────────────────────────▼──────────────────────────────┐
│ L2 安全拦截层  SecurityInterceptor                                        │
│    源 IP 解析 → 黑名单 → 滑动窗口限流 → 登录防爆破 → 载荷过滤 → 安全响应头  │
│    → 访问审计入队（异步落库，不阻塞业务线程）                              │
├──────────────────────────────────────────────────────────────────────────┤
│ L3 身份鉴权层  JwtInterceptor → AdminInterceptor / MerchantInterceptor     │
├──────────────────────────────────────────────────────────────────────────┤
│ L4 业务服务层  Order / AfterSale / Withdraw / Product / SecOps Service     │
├──────────────────────────────────────────────────────────────────────────┤
│ L5 持久层  MyBatis-Plus → H2（演示）/ MySQL 8（正式），共 20 张表           │
└──────────────────────────────────────────────────────────────────────────┘
```

网络侧设计要点：

- **组网与地址规划**：B/S 分层拓扑，客户端 / 接入层 / 应用服务层 / 数据层分离，
  预留按业务与管理网段的 VLAN 与 IP 分区；演示环境单端口 8080，正式环境由 Nginx 接入。
- **协议**：HTTP/1.1 + JSON 统一响应（`code/message/data`），完整使用
  200 / 400 / 401 / 403 / 404 / 405 / 429 / 500 状态码；CORS 预检放行；
  反向代理场景按 `X-Forwarded-For` 首段还原真实源 IP。
- **安全**：IP 黑名单（内存缓存 + 持久化 + 到期失效）、每 IP 每分钟 120 次全局限流、
  登录接口每 IP 每分钟 8 次阈值与自动封禁、XSS / SQL 注入 / 路径穿越特征过滤、
  `X-Content-Type-Options` / `X-Frame-Options` / `Referrer-Policy` / CSP Report-Only。
- **运维与 AI**：全量访问审计，按分钟聚合 QPS / 错误率 / 时延 / 源 IP 分布 / 慢接口；
  对四类指标建立 EWMA 动态基线（α = 0.30），用带量纲下限的 z-score 计算加权异常评分，
  综合评分 ≥ 3.0 时自动生成 QPS_SPIKE / ERROR_RATE / SLOW_RESPONSE / IP_BURST 告警，
  并支持流量回放验证算法有效性。

## 五、六项关键设计

1. **店铺数据边界**：商品、订单、售后、评价均带 `merchant_id`，商家端所有查询与更新
   都以当前登录商家的店铺标识为过滤条件，越权访问在 Service 层直接拒绝。
2. **按店铺拆单与运费分摊**：一次结算含多家店铺商品时按 `merchantId` 分组生成多笔订单，
   每笔独立计算运费（满 99 免运），整单优惠券按各子订单金额占比分摊，最后一单兜底。
3. **条件更新防超卖**：库存扣减不是「先查后写」，而是
   `UPDATE t_product SET stock = stock - n, sales = sales + n WHERE id = ? AND stock >= n`，
   依靠行锁与条件匹配保证并发下不出现负库存；影响 0 行即抛异常并回滚整单。
4. **资金账目闭环**：订单确认收货时 `balance = balance + 实付金额`；
   售后退款与提现审核通过时 `balance = balance - 金额`，
   两类金额变动都落在同一张 `t_merchant.balance` 上，钱包概览可完整对账。
5. **售后状态机**：仅退款 `0 → 3 / 4`，退货退款 `0 → 1 → 2 → 3 / 4`，
   买家可在 `0 / 1` 撤销（`5`）；重复处理、越权、错误状态均有校验；
   后端 `fillText` 与前端状态机镜像互校，避免展示文案缺失。
6. **智能运维监测**：用动态基线替代固定阈值告警，解决流量天然波动导致的误报，
   并把安全拦截产生的 403 / 429 记录沉淀为可查询、可统计、可回放的审计数据。

## 六、质量保障

- 后端 41 个 JUnit 5 用例（单元 + MockMvc 集成，H2 内存库，无需 MySQL）；
- 前端 20 个 Vitest 用例（展示工具、响应判定、状态机镜像、API 契约）；
- 端到端 31 条分层回归断言（Node 内置 `node:test`，零第三方依赖，只读可重复跑）；
- `tests/diagnose.mjs` 逐层体检脚本，输出第一个失败层与排查建议；
- `docs/TESTING.md` 断言清单、`docs/TROUBLESHOOTING.md` 分层排障手册；
- GitHub Actions CI：push / PR 自动跑后端测试、前端测试、前端构建与端到端回归。

## 七、运行方式

```bash
# 演示模式（H2 内存库，不需要 MySQL）
cd backend && mvn spring-boot:run -Dspring-boot.run.profiles=demo
# 或打包后直接运行
java -jar backend/target/life-shop-server.jar --spring.profiles.active=demo
# 访问 http://127.0.0.1:8080

# 前端开发模式（热更新，/api 代理到 8080）
cd frontend && npm ci && npm run dev
```

演示账号：买家 `zhangsan / 123456`，商家 `shop_kitchen / 123456`，管理员 `admin / admin123`。
